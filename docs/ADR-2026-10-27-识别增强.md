# 架构决策记录：发票识别增强（OCR 级联 + 模板抽取 + 审阅队列 + 去重）

> 日期：2026-10-27 ｜ 评审人：Zy（用户逐项确认）＋ lead 执行 ｜ 关联需求：报销处理从「文字版 PDF 专用」升级为「扫描件可识别、抽取可配置、人工兜底有 UI、重复可拦截」
> 流程：devbase-arch-review（引入改变核心抽取层/依赖/打包形态的模块，出 ADR 后动码）

## 约束（继承项目既有 ADR，未变项不重审）

- 部署形态：单机 Windows 桌面 exe（pywebview 壳），域控环境
- 离线：纯本地处理，OCR/模板/AI 全部离线可用（AI 审核为可选开关）
- 数据规模：单任务百级 PDF，历史归档万级文件
- 任务时长：分钟级，单任务槽 + 取消事件（不变）
- 权限：单用户本地 token（不变）

## 本次决策（4 项）

### D1 OCR 级联（改动最大，先做）

- **决策**：引入 RapidOCR（PaddleOCR 模型 → ONNX + onnxruntime，Apache-2.0，纯离线）作为 `core/pdf_text.py` 的级联后端。pdfplumber 抽出**有效文本**（非空且达到最小长度阈值）→ 直接用；抽不出/过短 → 页转图（pypdfium2 或 pdf2image+PyMuPDF 渲染，倾向 pypdfium2 纯 Python）→ OCR 得文字层 → 进入既有抽取流程。
- **失败路径**：OCR 后仍无有效文本 → 文件落入既有「需人工处理」目录（用户确认的兜底语义），计 warning，不中断任务。
- **开关**：config.ini `[ai]` 段新增 `ocr_enabled`（默认 true），关闭即回到纯 pdfplumber 行为；OCR 可用时日志标注来源（`text(pdfplumber)` / `ocr(rapidocr)`）。
- **理由**：RapidOCR 无 torch/paddle 重依赖、onnxruntime CPU 推理打包体积可控（约 +30~60MB，用户确认体积不敏感）、中文精度接近 PaddleOCR 原生、pyinstaller 兼容性已知良好。
- **何时重审**：识别率实测低于预期 / 打包体积超 100MB / 出现更轻的中文 OCR 方案。

### D2 抽取模板化（invoice2data 模式）

- **决策**：`core/templates/` 目录按开票方/票种放 YAML 模板（issuer 关键词 + 字段正则：金额、日期、发票号、行程起止等），运行时模板优先匹配文本，命中即产出结构化字段；现有 7 个 `process_xxx` 硬编码处理器（浙江/江苏/高铁/滴滴/过路费/通用…）**全部保留兜底**——模板不命中的票种走原逻辑，行为不变（用户确认：全部可正常处理后再评估移除硬编码）。
- **理由**：新增开票方从改代码降为加配置；AI 审核降为模板/规则不命中时的辅助而非主路径。
- **何时重审**：模板覆盖率 ≥95% 且连续两个版本零误判，可开始退役硬编码。

### D3 审阅队列 UI

- **决策**：处理页（ProcessingView）结果区内嵌「需人工处理」清单 UI：任务完成后列出该批次转入人工目录的文件（文件名 + 原因），提供「打开文件夹」按钮；schema 增补需人工文件清单字段，随任务快照下发。
- **理由**：把死胡同变成可操作入口；不加新页面，改动收敛在结果区。

### D4 重复检测（全局内容哈希）

- **决策**：任务处理阶段对每个 PDF 计算 sha256（流式读取），落 `output_dir/重复文件检测.json` 或等价索引（随归档语义进「已处理」目录）；命中同批或历史归档（同 hash 已存在）→ 文件标「重复」跳过处理并计数提示，不移动、不归档。范围：全局（按内容，不按文件名）。
- **理由**：防同一张发票重复报销（审核场景真需求）；半小时级工作量，随本批次一并落地。

## 实施顺序（用户确认：按架构改动从高到低）

1. **OCR 级联**（D1）→ 2. **抽取模板化**（D2）→ 3. **审阅队列 UI**（D3）→ 4. **重复检测**（D4）

每阶段独立可验收、可回滚（D1 有开关，D2 有兜底，D3/D4 纯增量）；全量 pytest/契约/前端门禁每阶段末跑一次。

## 偏离模板默认项

| 项 | 偏离内容 | 原因 | 替代方案 / 回滚 |
|---|---|---|---|

## 团队分工（执行阶段）

- **ocr-int**：D1（pdf_text 级联 + config 开关 + 渲染依赖 + 测试）
- **tmpl-int**：D2（templates 目录 + 模板引擎 + 与 classify/process_xxx 兜底衔接 + 测试）

## 重审触发条件

- OCR 打包体积超 100MB 或启动时间明显劣化
- 模板误判率上升（连续版本出现金额/日期抽错）
- 归档索引超过 5 万条导致哈希比对变慢（届时改 SQLite 索引）
