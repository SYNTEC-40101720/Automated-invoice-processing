## 拆分 InvoiceProcessor 上帝类为多模块（10:30 起）

用户要求把 600+ 行的 `InvoiceProcessor` 按职责拆成小模块。验证：全量 79 passed（核心 63 + ai_audit/email_pull 16）。

### 新模块（src/core/）
- `pdf_text.py` → `PdfTextExtractor`：PDF 文本提取 + 双缓存 + 日志 + 缓存复制（纯 I/O，零业务）
- `invoice_output.py` → `InvoiceOutputWriter`：金额标准化、文件名去重、内容哈希去重、输出文件生成、税号异常归集。持有 `PdfTextExtractor` 引用以复用 `_copy_cache_entry`/`_log_core`
- `invoice_types.py`：`register_type` 装饰器 + `_TYPE_REGISTRY` + 各类型处理逻辑（函数，接收 processor 外观复用能力）+ `determine_processor_type`
- `pdf_merge.py` → `PdfMerger` + `classify_invoice`：合并与分类（消除原 post_process/merge_pdfs 重复规则）
- `processor.py`：`InvoiceProcessor` 外观，组合三者并编排 `post_process`；所有公共/测试依赖方法保留为**薄委托**

### 保住的两个硬约束（关键）
1. `test_routing_returns_correct_handler` 断言 `proc.determine_processor_type(...) == proc.process_jiangsu_invoice` —— 返回 handler 必须是 `proc` 上的方法对象。故 `process_*` 仍作为 `InvoiceProcessor` 上的薄方法（对象身份不变），逻辑实现移到 `invoice_types` 函数。`determine_processor_type` 返回 `getattr(processor, method_name)`。
2. `excel_summary.py` 直接用了 `processor.extract_pdf_text_with_error` 和 **`processor._extract_raw_text`（私有）**；`tests` 还直接调 `proc._extract_raw_text`/`_claim_output_name`/`_generate_output_file`/`_PREFIX_SUFFIX`/`_TYPE_REGISTRY`。`InvoiceProcessor` 全部保留这些（内部委托），并从新模块再导出 `_PREFIX_SUFFIX`/`_TYPE_REGISTRY`/`register_type`。

### 复用价值（未来重构范式）
"上帝类拆分"若遇紧耦合测试契约（方法对象 `==` 比较、外部模块调私有方法），用**外观 + 薄委托方法 / staticmethod / 再导出模块常量**即可让公共面逐字节不变，测试零改动。切勿为拆而拆——能隔离的纯 I/O（如 PdfTextExtractor）收益最大。
